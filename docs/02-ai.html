AI 활용 기술 문서

힘을 내 히키코모리 · NHN NAN 2026 해커톤 사전 과제 · 개인 참가

이 게임에서 AI는 대사를 예쁘게 써주는 도구가 아니라 게임의 규칙 엔진이다. 고정 NPC도, 고정 대사도, 고정 이벤트도 없다. 매일 밤 AI가 그날의 행동과 대화 원문을 읽고 가설을 세우고 · 채점하고 · 내일의 무대를 편성한다. 게임이 언제 끝나는지도 AI의 결론이 정한다.

1. 전체 구조

브라우저 (Phaser 3, 번들러 없음)
   │  fetch('/api/agent/<name>')            ← API 키는 클라이언트에 없다
   ▼
Node.js 얇은 프록시  (server/index.mjs)      ← 정적 파일 + API를 한 서버가 서빙
   │  server/agents.mjs   에이전트 10개 등록 · 공통 실행기 · JSON 스키마 강제
   │  server/prompts.mjs  prompts/*.md 를 파일에서 직접 읽는다 (코드에 복붙하지 않음)
   │  server/hypothesis.mjs  confidence 이동 · status 판정 (코드의 몫)
   │  server/cache.mjs   동일 입력 캐시
   ▼
Anthropic API — 모델 claude-opus-5 (전 에이전트 공통), 구조화 출력(JSON Schema)

설계 원칙 넷

  1. 역할이 다른 AI를 나눈다. 분석과 생성은 요구가 정반대다 — 분석은 스키마가 흔들리면 안 되고 일관성이 전부이며, 생성은 매번 달라야 한다. 합치면 JSON을 강제하는 순간 대사가 딱딱해지고, 대사에 집중하면 스키마가 흔들린다.
  2. 세우는 쪽과 채점하는 쪽을 나눈다. analyst는 가설의 문장과 근거만 낸다. confidence를 움직이는 것은 referee의 판정이고, 실제로 값을 옮기고 confirmed를 판정하는 것은 코드(hypothesis.mjs)다. 자기 숙제를 자기가 채점하면 반증이 불가능하다.
  3. 프롬프트로 지킬 수 없는 규칙은 코드로 막는다. "하루에 한 명만 흘려라" 같은 빈도 제약을 프롬프트는 지키지 못한다. 조건은 전부 코드가 판정한다(wants.js canDrop()).
  4. 키는 서버 프로세스 밖으로 나가지 않는다. 모든 호출은 프록시를 경유하며 클라이언트에 키가 없다.

   ├─ 관측 로그 + 대화 원문 + 어제의 가설 테이블을 모은다
   ▼

같은 행동도 이유가 다르면 다른 신호다. 구분이 없으면 분석 AI가 매번 다르게 지어낸다.

4. 주요 프롬프트와 지시 사항

프롬프트 원본 10개는 저장소의 prompts/*.md에 그대로 있으며, 서버가 이 파일을 직접 읽는다. 코드에 복붙된 사본이 없어 문서와 실제 동작이 어긋날 수 없다. 아래는 핵심 지시 발췌다.

analyst — 가설을 세우되 채점하지 않는다

묻는 것은 "이 사람의 입이 어떻게 열리는가"다 — 누구에게, 무엇을 매개로, 언제.

이 AI는 점수를 매기지 않는다. confidence는 referee의 판정에 따라 코드가 상수만큼 움직이고, verified_count도 코드가 센다. status·confirmed 판정 역시 코드의 몫이다. 세우는 쪽과 채점하는 쪽을 나눠야 반증이 가능하다 — 자기 숙제를 자기가 채점하면 안 된다. 이 AI가 낼 것은 가설의 문장과 근거뿐이다.

또한 전 프롬프트에 걸린 공통 제약: 심리학자처럼 읽되 진단명은 절대 붙이지 않는다. 관찰에서 멈추지 않고 그 회피가 무엇을 막아주나 / 그 바람을 무엇으로 대신하고 있나까지 가되, 병명·장애명으로 요약하지 않는다.

director — 이벤트는 아직 모르는 것을 향해 던진다

밀도를 채우는 장식이 아니라 아직 모르는 것(과거·상처·두려움·바람)을 향해 던진다. 직접 묻지 않는다 — "왜 그랬어?"는 문을 닫는다. 곁에 두고 스치게 한다. 세 번 던져 안 걸리면 그 방향이 아닌 것이고, 그것도 답이다.

confide — 플레이어를 닮은 고민을 만들지 마라

그건 골 맵의 거울이 하는 일이고 게임의 마지막 한 방이다. 매일 그러면 거울이 죽는다.
만들 것은 같은 신경을 건드리는 남의 고민 — 보인 것 옆이지 그것 자체가 아니다. 
피한다 → ✗ "나도 사람이 무서워"   ✓ "형이랑 3년째 말을 안 해"
미룬다 → ✗ "나도 다 미루고 있어"  ✓ "부모님이 아직 모르셔"

mirror — 이 게임의 마지막 장면

사람은 자기 문제를 자기한테는 못 풀어준다. 그런데 같은 처지의 남에게는 풀어준다. 플레이어가 이 인물에게 뭐라고 해주는 순간, 그건 자기가 자기한테 한 말이 된다. 게임이 할 일은 그 말을 받아내는 것뿐이고, 그다음엔 사라지는 것이다.

거울 인물에게는 드러내지 않는다는 제약이 걸려 있다 — "너도 그렇지?"라고 묻는 순간 끝이다. 알아채는 것은 플레이어의 몫이며, 마지막에 플레이어가 해준 말을 그대로 인용한다.

공통 — 코드가 실행할 수 있는 것만 약속한다

NPC가 한 약속("방으로 가져다줄게")은 place / move / give 세 가지 효과로만 받는다. 코드가 모르는 효과는 조용히 버린다 — 지어낸 약속을 못 지키면 그게 더 나쁘다. 그리고 곧바로 일어나지 않는다. 말하자마자 생기면 마술이고, "이따"는 이따 일어나야 약속이 된다.

구조화 출력 (JSON Schema)

모든 에이전트는 output_config.format = json_schema로 호출된다. 스키마는 server/agents.mjs에 정의되며, 일부는 클라이언트 코드의 enum을 그대로 import해 클라이언트 검증과 어긋날 수 없게 했다.

// server/agents.mjs
import { TYPES, WALL_POSITIONS, FLOOR_POSITIONS, SIZES } from '../src/room/schema.js';
// → 방 사진 인식 결과의 오브젝트 type/position/size enum이 렌더러와 같은 출처를 쓴다

// NPC가 흘리는 물건(want)의 enum = 편의점 재고(shop.ORDER)
// → 팔지 않는 물건을 원하는 일이 구조적으로 불가능하다

5. AI 실패를 다루는 방식

  • 실패는 콘솔이 아니라 보는 자리에 적는다. API 호출이 죽으면 화면 상단에 ⚠ AI 연결 실패 — 이벤트가 생성되지 않는다가 뜬다. 이 표시가 없어서 배포본 키가 401인 채로 나흘이 지난 적이 있다 — 이벤트도 NPC도 0건인데 화면에 아무 표시가 없으니 게임이 원래 그런 줄 알게 된다.
  • 응답을 기다리는 데는 반드시 시한이 있다(25초). 없으면 응답이 안 올 때 대화창이 영영 안 닫히고, 대화 중에는 이동도 막히므로 게임이 통째로 멈춘다(실제로 멈췄다).
  • 읽던 글은 어떤 경우에도 화면에서 사라지지 않는다. 생성이 실패해도 갑자기 닫지 않고 [Space]로 닫게 한다. 답장이 없는 것도 이 게임에서는 흔한 일이고, 그 자체가 자료다.
  • 동일 입력에 대한 응답 캐시(server/cache.mjs)로 개발 중 반복 호출 비용을 줄였다.

6. 개발에 사용한 AI 도구

도구용도
Claude Code (Claude Opus 5) 설계 논의, 코드 작성·리팩터링, 프롬프트 작성, 테스트 작성, 브라우저 자동화 기반 동작 검증. 저장소의 CLAUDE.md가 프로젝트 상시 지침으로 사용되었고, PROGRESS.md에 일자별 의사결정 기록이 남아 있다.
Anthropic API (claude-opus-5) 게임 런타임의 AI 전부 — 위 10개 에이전트. 비전(방 인식·현실 인증), 추론(가설·편성), 생성(대사·골 맵).

게임 내 텍스트(대사·이벤트·골 맵)는 실행 시점에 Anthropic API가 생성하며, 설계 문서와 코드 주석은 개발자가 Claude Code와 협업해 작성했다. 플레이 영상은 실제 플레이 화면을 그대로 녹화한 것으로, 합성이나 편집으로 만든 장면이 없다.

7. 외부 에셋 · 오픈소스 출처

그래픽 · 사운드 — 외부 에셋 없음

이 프로젝트는 외부 이미지·타일셋·사운드 에셋을 사용하지 않는다. 모든 그래픽(바닥·벽·가구·캐릭터·UI)은 실행 시점에 src/render/textures.js가 Phaser Graphics로 코드에서 직접 그린다. 사운드는 사용하지 않는다. 폰트는 사용자 시스템의 monospace / Malgun Gothic을 사용하며 폰트 파일을 배포하지 않는다.

8. 개인정보 · 데이터 취급

  • 방 사진과 현실 인증 사진은 저장하지 않는다. 브라우저에서 축소해 전송하고, 서버는 모델에 넘긴 뒤 즉시 버린다. 디스크에 쓰지 않는다.
  • API 키는 서버 환경변수로만 존재하며 클라이언트 번들과 저장소에 포함되지 않는다(.env는 커밋 제외).
  • 진행 상황은 플레이어 브라우저의 localStorage에만 저장된다. 서버는 플레이어를 식별하지 않고 계정도 없다.
  • 플레이어가 직접 입력한 문장은 요약하지 않고 원문 그대로 게임 세션 내에 보관해 AI 입력으로 쓴다. 세션이 끝나면(새 게임) 함께 사라진다.
